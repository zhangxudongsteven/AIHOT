# 后台频道管理：实现与本地验证

日期：2026-10-28，Asia/Shanghai。基线为 `main@8a46aed`，开发分支为 `codex/admin-channel-console`。

## 已实现范围

- 后台管理范围分为平台、AI 与网络安全；频道身份固定在 URL，可在独立标签页分别管理。
- 频道信源列表、新建、编辑、预览及采集使用所属频道的管理接口；旧信源网址固定跳转至 AI。
- 模型请求额度独立显示频道用量与平台上限，普通上限编辑在事务内保留最新预留容量。
- 飞书内容目标使用已登记群标识；不新增 Webhook 编辑或密钥存储。空槽需要明确选择群，未知历史引用仅可暂停，缺凭据不能开启。
- 频道表单的未保存提示、迟到响应、创建后的导航及幂等身份按频道和对象隔离；保存及重新读取期间暂停编辑，避免丢失新草稿。
- 平台二维码、运维通知及平台总额度保持共享；模型配置和 SelectBench 明确标注默认 AI 范围，调用统计标注全站。

管理 API 延续管理员会话、CSRF 与审计。新增频道目录和受限群订阅入口，既有运维 API/CLI 继续兼容。无数据库迁移、公开协议变化、默认运营配置重写或新依赖。

测试使用独立 `_ci` 数据库和本地假服务，不调用真实模型或发送真实消息。后端第一轮完整检查发现测试容器缺少 Git 和最新 Web 源码挂载，修正容器后重新运行全量，通过结果来自完整当前源码。

新增行为覆盖：认证及 CSRF、未知/停用频道、跨频道来源拒绝、独立额度和使用量、并发预留容量保留、群 allowlist、空槽准备、未知旧目标停用及原有不补发规则；浏览器覆盖桌面与手机、深链接、双标签页、未保存切换、迟到预览/创建、幂等身份和实际归属链接。

两个保存边界先复现再修复：页面打开后运维调整预留容量不会被旧表单覆盖；提交和重新读取期间不能继续编辑底层表单，完成后新编辑仍触发离开提示。

固定提交评审另发现运维路由接管的并发窗口，使用真实数据库行锁先复现再修复。网页现在在既有行锁事务和 UPSERT 冲突更新条件中重新检查路由保护；已存在目标、并发首次插入和暂停时的用途/类型/引用变化均有回归，旧运维入口继续兼容。
