## 采样与评分方法

- arXiv 官方查询 API；窗口为最近 30 天，按 submittedDate 倒序，start=0、max_results=3；两个分类串行读取并限速。
- 关键词限定 retrieval augmented、retrieval-augmented、带 retrieval/generation 上下文的标题 RAG，以及 retrieval 与 evaluation/benchmark 的组合。没有使用大模型、Agent 等泛主题扩充候选。
- cs.CL 窗口内匹配 124 条，cs.AI 匹配 133 条；这是查询匹配量，不是本轮采集量或去重后的日新增量。完整表达式和 URL 见证据。
- 按不带版本号的 arXiv ID 跨分类去重；本轮重复项是同一 v1 且摘要一致，只评分一次。其他不同版本的合并策略未在本轮验收。
- 试评时可用模型额度有限。为在既有额度内完成，本轮先按题名和摘要逐篇核对其属于用户指定主题，再直接执行现有两次独立评分；没有额外调用模型相关性预筛，不把主题核对伪记为模型 PASS。
- 沿用现有 T1 门槛 60（只在本次内存评估中使用），两次评分之和至少 120 即通过，展示分为均值向下取整。未修改提示词、门槛、模型或来源分级配置。
- 仅使用作者原始摘要。模型输入明确标注“仅摘要、未读取全文、实验结论为作者主张”；未读取 PDF、复现实验或核验同行评审状态。入选列表示“主题符合且双评分达到门槛”的试评结论，不代表网站实际发布。
- 日期取官方 API 的 published（首版提交处理时间），updated 单独留存；本轮均为 v1，二者相同。下表统一显示北京时间。

以下中文概述仅转述作者摘要，不表示本轮已经核实实验结论。

- **CoverageBench-Negate：矛盾证据检索评测**：构造受控的否定证据，检验检索器是否能找到与模型先验冲突的材料。作者在该基准上比较 BM25 和稠密检索器，讨论语义相关性与事实矛盾识别的差别。
- **SpectRAG：多跳检索的上下文选择**：把文档块组织为加权图，结合混合检索、图扩展和谱相关性，在固定 token 预算下选择上下文。摘要报告证据覆盖改善，也指出精度、计算成本和领域差异的权衡。
- **RAG 知识冲突分类的决策模型**：比较决策模型与生成式 LLM 对检索来源冲突的分类能力，并按模型不确定性做级联。作者报告成本和延迟优势，同时指出准确率、虚假来源识别及顺序敏感性方面的局限。
- **流程知识图谱辅助企业 Agent 检索**：把 OData 元数据与 BPMN 业务流程组织为类型化图，在发现服务端点时同时检索流程和结构约束。作者在限定企业服务任务中报告多步调用可靠性改善，缺少流程层时未见同类收益。
- **RouteDRAG：多模态文档 RAG 路由**：根据查询预测是否需要 Agent，再动态控制工具使用与终止。作者在两个基准上报告，相比统一执行 Agent，该方法以较少调用取得更好的准确率。
