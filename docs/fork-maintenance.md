## 版本与记录分工

| 记录 | 职责 |
| --- | --- |
| [`CHANGELOG.md`](../CHANGELOG.md) | 本项目开发者发布记录。项目版本从 4.1.0 继续独立维护；日常改动先进入“未发布”，确定发布范围时再归档版本。 |
| [`site/changelog.json`](../site/changelog.json) | 本站读者看到的更新，只描述本项目实际交付或明确标注的开发版本。移除继承的“网站上线”示例，不能把示例时间当作本站上线事实。 |
| [`site/site.ts`](../site/site.ts) 的 `SITE.interfaceVersion` | 公开协议版本，目前为 4.1.0，由 MCP、OpenAPI 和 `llms.txt` 共用。按接口兼容性演进；纯文档、内部改动不自动升接口版本。 |
| [`docs/known-issues.md`](known-issues.md) | 持续跟踪已知缺陷；4.2.0 已修复 MS-001、MS-003、MS-005、MS-006（`e341acb`），其余三项保持 Open。只有修复实现、对应回归通过并记录提交后才关闭。 |
| `docs/reports/` | 各阶段和评审的历史证据。后续决定另作补充，不把当时的实现、验证或部署状态改写为新状态。 |

当前项目源码版本为 4.2.0，公开协议版本保持 4.1.0；项目版本通过 CHANGELOG 和 `v<版本>` Git 标签记录，协议版本按接口兼容性独立演进。网站日志的 `latestVersion` 是日期时间通知标识，必须与最新条目的 `date`、`time` 一致，不能拿它当作语义版本。

站点日志和开发者日志没有自动生成关系：面向读者的变化发布时同时维护两处；纯开发工具或维护约定可以只记开发者日志。发布记录应区分实现、本地验证、业务验收和已部署；本地提交不意味着远程发布或线上完成。
